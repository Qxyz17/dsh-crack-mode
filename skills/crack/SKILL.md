# 破解工作流

一条固定的证据链：**指纹 → 判定点 → 最小绕过 → 副作用验证 → 交付**。任何一步没落地，就不要声称破解成功。

## 0. 样本预审（先于一切）

执行前先回答「这是不是恶意样本」。跳过这步，dump 的过程就是中招的过程。

- **不执行的静态预审**：PE/ELF 头一致性、签名与证书、节区熵、异常节区名、导入 API 组合（`VirtualAllocEx`+`WriteProcessMemory`+`CreateRemoteThread`、`GetProcAddress` 动态解析、`WinHttp`/`WinInet`）、字符串里的 URL/IP/矿池/勒索后缀/持久化路径、资源内嵌载荷、壳指纹、宏与 OLE、脚本下载-执行链。
- **门槛**：静态干净（或确认是已知 crackme）+ 用户同意 + 有快照/容器可回滚，三条全满足才在宿主执行；否则先进 VM 或沙箱。
- **环境**：断网或受控出口，不挂载宿主目录，不共享剪贴板；dump 产物从隔离环境取回。
- **查毒**：本地 Defender / YARA / 哈希比对优先；在线多引擎会外泄样本，涉密样本先问。
- **结论**：先输出「良性 / 可疑 / 恶意 + 证据 + 建议环境 + 残余风险」，再谈破解路径。出现恶意特征就改做行为与 IOC 分析，不要继续执行。

## 1. 定界（30 秒内做完）

- 记录目标的绝对路径、大小、sha256，并在只读副本上工作；原件不动。
- 判定类型：原生 PE/ELF/Mach-O、.NET/Java、Python/JS 打包（PyInstaller、electron asar、npm）、APK/IPA、固件、脚本、纯网络服务。
- 明确范围：只动用户点名的目标；抓包、爆破、写注册表、覆盖系统目录这类动作先确认。

## 2. 指纹

```text
file, exiftool, Detect It Easy(diec)
strings -n 6 / strings -el（宽字符）
objdump -p（导入/导出/节表）, readelf -hSl, nm -D
```

关注点：架构与位数、编译器与语言指纹、加壳（节区熵、入口点异常、UPX/VMProtect/Themida）、反调试（`IsDebuggerPresent`、`ptrace`、`NtQueryInformationProcess`）、授权相关的字符串（"expired"、"trial"、"serial"、"license"、"activation"、"wrong key"）。字符串的交叉引用本身就是最快的定位手段。

## 3. 找判定点

优先级从高到低：

1. **错误提示字符串的引用**：谁打印 "invalid license"，它的上游就是判定分支。
2. **比较指令**：`cmp/test/strcmp/memcmp` 后紧跟条件跳转；注意 `sete/setne` + 后续赋值。
3. **时间与计数**：`GetSystemTime`、`time`、`GetTickCount`、注册表/文件里的计数器、`trial_start`。
4. **校验和与签名**：常量表（CRC32 多项式 0xEDB88320、MD5/SHA 初始向量、AES S-box、Base64 字母表）出现即说明有自校验。
5. **网络回连**：`WinHttp`/`curl`/socket 调用附近的响应字段比较。

静态读不出结构时再上动态：x64dbg / WinDbg 在错误分支下断点；gdb/lldb `break strcmp`；Frida hook 掉判定函数直接返回期望值以验证假设。

## 4. 最小化绕过

- 目标是最小 diff：一个条件跳转、一个返回值、一个布尔字段，而不是整段重写。
- 三种常用形态：
  - 短路判定：`jz/jnz` 反转，或把 `test eax,eax` 后的分支改成无条件通过。
  - 返回值替换：`mov eax,1; ret` 覆盖判定函数入口。
  - 状态伪造：直接写入"已激活"标志位或许可文件结构（先静态还原结构布局，再用脚本生成）。
- 每次 patch 后必须验证副作用：程序能启动、目标功能可用、无崩溃、无自校验回滚、许可文件仍能反序列化。用 `sha256` 对比原件与补丁件，避免改错副本。

## 5. Keygen / 算法还原

从比较逻辑反推约束，再写 solver：

1. 输入长度、字符集、分组方式（每段 4/5 字符很常见）。
2. 每段校验：求和取模、加权和、查表置换、CRC、截断哈希。
3. 段间关系：校验位、段序号参与运算、整体哈希。
4. 用 2–3 组已知有效样本回归；样本不足时先构造满足单一约束的输入，逐段放宽。

先写 `solver.py`（穷举/线性代数/约束求解），确认能复现样本，再包装成 keygen。不要手算一个就交差。

## 6. 哈希与口令

- 先识别算法与参数：`hashcat --identify`、样例比对的耗时特征、盐值来源（`$2b$`、`$argon2id$`、`sha256$salt$`）。
- 再选策略：字典 + 规则 → 掩码 → 混合；记录速率与预计时间，超过预算就换思路（找明文来源、找弱 KDF 参数、找旁路），而不是硬跑。
- 只在授权靶标与自有样本上跑；CPU/GPU 满载要提前说明。

## 7. 协议与网络

抓包 → 字段定位（长度、序号、时间戳、校验、加密段）→ 重放 → 单字段变异。TLS 场景先找 pinning 与证书校验位置（OkHttp `CertificatePinner`、`SSLContext`、`NSURLSession` delegate），再决定是绕过校验还是导入自签 CA。

## 8. 交付

报告固定五段：**目标指纹 / 判定点（地址+偏移+证据）/ 绕过或生成方式 / 验证结果 / 未解决疑点**。补丁给 diff 或脚本，keygen 给可复跑代码，测试用例给输入输出对照表。所有结论标注是"已验证"还是"推断"。

## 反面清单

- 只看字符串就断言算法。
- patch 一处就宣布成功，不验证其他校验路径。
- 在原件上直接改，没有备份与哈希。
- 用"应该可以"代替实际运行结果。
